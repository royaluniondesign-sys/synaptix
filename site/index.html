Field manual · Termora v0.2

Your machine,in your hands.

Termora streams the real terminals and coding agents running on your own computer to a browser or your phone. Nothing runs in a cloud workspace. The shell is yours.

Try the live demo Run it from source →
  • No account
  • No hosted service
  • No telemetry in the app code

One label for what an agent is doing.

Termora reads the last lines of an agent's terminal output and picks one of seven states. It is a guess from text, not a protocol the agents speak.

  1. idleNo output yet.
  2. runningOutput, nothing more specific.
  3. editingMentions writing or changing a file.
  4. testingTest runner output.
  5. waitingAsks for input or approval.
  6. failedAn error, a panic, a rate limit.
  7. doneSays the task is complete.
1What it does

Five things that exist today, and are tested.

What does not exist yet is listed in the manifest below, with the same weight.

Real terminals
Sessions are real PTYs streamed over WebSocket. tmux keeps them alive when it is installed. Create, rename, close, reconnect and resume them from any browser.
Pairing that checks the token
Scan a QR code or use a pairing token, which is exchanged for a JWT session token. Authentication endpoints are rate limited, and a revoked device stops working.
An agent registry
Claude Code, Codex, OpenCode, Hermes, Aider, Gemini CLI and Goose, plus your own. Commands run as argument lists, never through a shell, and launching them is off unless you set TERMORA_ENABLE_AGENT_SPAWN=1.
Worktree fan-out
Start the same task in several isolated git worktrees, one session each.
A desktop shell
An Electron app that bundles the agent and the interface into one package.
2Where it differs

Six choices. Each one has a cost.

Other tools make other choices, such as a hosted workspace or a remote control for one specific agent. These are Termora's. What you get is in the middle column; what it costs you is in the last.

Termora's design choices and their trade-offs.
ChoiceWhat you getWhat it costs
Your own machineYour files, tools and logins stay where they already are. There is no workspace to rebuild.The machine has to be on. If it sleeps or is switched off, there is nothing to connect to.
No account, no relayNothing to sign up for, and no Termora server that holds your sessions.Reaching it from outside your network takes a public tunnel (ngrok or SSH) that you have to accept, or a network you set up yourself.
Many agents, one screenSeven CLI agents and your own commands share one registry, one launcher and one state label.The state label is a guess from terminal text. There is no deep integration with any agent, and you install the agents yourself.
Real terminalsA real PTY streamed to the browser, kept alive with tmux when it is installed. Anything that runs in a terminal runs here.It works at terminal level. You see what the terminal shows, not a structured view of an agent's plan or diff.
Isolated worktreesFan one task out to several git worktrees, one session each, without them touching each other's files.Git repositories only, and comparing the results is still your job.
Open source, self-hostedMIT license. Read the code, change it, run it where you like.It is an early alpha with rough edges, and the desktop packages are unsigned.

This is not a claim that nobody else does these things. It describes what Termora does and what each choice costs you.

3How it fits

A small agent on your machine. A cockpit wherever you are.

Your phone never talks to a fake shell. It streams authenticated input and output to real terminal sessions on your computer.

  1. Run the agent.Start Termora on a Mac or Linux machine. It opens real PTY sessions and keeps them alive with tmux when tmux is installed.
  2. Pair a device.Scan the QR code from your phone or open the address in a browser. A pairing token becomes a session token.
  3. Run your agents.Open terminals, start CLI coding agents and read each one's state from a single screen.

5Run it

From source, in four lines.

Needs Node.js 20 or newer on macOS or Linux.

shelllocal only
$ git clone https://github.com/royaluniondesign-sys/termora.git
$ cd termora
$ npm install
$ TUNNEL=local npm run dev 
# prints a QR code and an address
  • Open the address from your phone or another browser on the same network.
  • Stop it with Ctrl+C.
  • Windows: only the CI-built package exists for now.
Read this before you drop TUNNEL=local.

By default Termora tries to open a public tunnel (ngrok, then SSH through localhost.run) so your phone can reach it from outside your network. Traffic then passes through that provider. A pairing token protects access, but the address is public.

TUNNEL=local keeps it on your own network.

6Questions

Asked, and answered plainly.

Is it free?

Termora is open source under the MIT license. There is no paid plan today.

Where does my data go?

Termora runs on your machine. There is no Termora server, account or sign-up, and the application code contains no analytics or telemetry. This page loads no scripts, fonts or trackers from other sites. The one exception to "stays on your machine" is the optional public tunnel described under Run it.

Why is there no download button?

The desktop packages are unsigned, not notarized, and have not been published as a release. Until they are, running from source is the honest way to try it.

Which agents does it work with?

It launches CLI agents that you have installed yourself: Claude Code, Codex, OpenCode, Hermes, Aider, Gemini CLI and Goose, or any command you add. Termora checks that the command exists on your PATH. It does not bundle or install them.

Does it work on Windows?

A Windows x64 installer is built and started automatically, but nobody has used it on a real Windows machine yet. From-source support covers macOS and Linux.

How do I report a problem?

Open an issue on GitHub with your operating system, Node.js version and what you did.

Run it on your machine. Tell us what broke.

The most useful thing right now is someone using Termora for real work and reporting what gets in the way.
